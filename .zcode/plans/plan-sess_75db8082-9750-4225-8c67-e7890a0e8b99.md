## Real-data map integration — NDVI raster (Sentinel-2) + weather zonal (Open-Meteo)

### Architecture: hybrid (the only thing that makes sense per layer)

| Layer | Source | Form on map |
|-------|--------|-------------|
| **ndvi** | Sentinel-2 via Sentinel Hub | **Raster tile overlay** (true intra-field imagery) |
| **temperature** | Open-Meteo (centroid) | Colored polygon (zonal scalar) |
| **gdd** | Open-Meteo temps → computed | Colored polygon |
| **dew** | Open-Meteo temp + humidity → estimated | Colored polygon |
| **moisture** | *stays mock* until IoT chosen | Colored polygon |

Two security invariants drive the design:
1. **`SENTINEL_CLIENT_ID` / `SENTINEL_SECRET` never reach the browser.** Sentinel Hub tiles are requested by Mapbox GL client-side, so they must be proxied through a server-side BFF route that injects the Bearer token. The client only ever sees our own `/api/tiles/...` URL.
2. **No new secrets in the browser.** Open-Meteo needs no key, but we still fetch it server-side (BFF) so the map stays a dumb consumer and we can cache/shape the response.

### The gap to close first (both paths share this)

Today the map imports mock arrays directly in `lib/geojson.ts` (`layerValueFor` reads `ndviSamples`/`weatherDays`/`sensorReadings`). Real providers won't take effect until the map reads through the provider/BFF layer. This refactor is Phase 1 and unblocks everything.

### Phase 1 — Close the gap + Open-Meteo (weather layers go live)

**1a. Decouple `lib/geojson.ts` from mock data**
- `fieldFeatures(layer, fields, values)` becomes a pure geometry+color function: it takes a pre-built `values` map (`{ [fieldId]: number | null }`) instead of computing from mock. `layerColor(layer, value)` stays here (you just fixed it — keep it). Geometry continues to come from the `fields` argument (client store).
- Remove the direct `import { ndviSamples, weatherDays, sensorReadings } from "@/lib/mock/data"`. Keep `seedFields` default only for non-map callers (none currently, but safe).

**1b. New `lib/map-values.ts` (server-only)** — `getMapLayerValues(date): Promise<Record<string, Record<MapLayer, number | null>>>`
- Calls `weatherProvider.getWeatherAt(field, date)` per field (parallel `Promise.all`), maps to `{ temperature, gdd, dew }`.
- Calls `sensorProvider` for moisture (stays mock-backed until IoT).
- Calls `satelliteProvider.getNdviAt(field, date)` for the NDVI *mean* (used by legend/DevicePanel; the raster imagery is separate).
- This is the server-side aggregation mirror of the existing `lib/metrics.ts`, scoped to "all fields, one date, all layers."

**1c. New BFF route `app/api/map/layers/route.ts`**
- `GET /api/map/layers?date=YYYY-MM-DD` → returns `{ [fieldId]: { ndvi, temperature, gdd, moisture, dew } }`.
- Server-only, calls `getMapLayerValues`. Adds `Cache-Control` (short, e.g. 60s) so rapid layer toggles don't refetch.

**1d. New `lib/providers/open-meteo.ts`** — `OpenMeteoWeatherProvider implements IWeatherProvider`
- `getWeatherAt(fieldId, asOf)`: fetch `https://api.open-meteo.com/v1/forecast?latitude&longitude&daily=temperature_2m_max,temperature_2m_min,temperature_2m_mean,relative_humidity_2m_mean,dew_point_2m_mean&start_date&end_date=asOf&past_days=92`, map response → `WeatherDay`.
- `getWeatherSeries(fieldId)`: same, broader date range.
- **GDD**: computed via new `lib/gdd.ts` util `computeGddCumulative(dailyMaxMin[], baseTempC)` — accumulates `max(0, ((Tmax+Tmin)/2) − baseTempC)`. `baseTempC` looked up from the field's crop (imports `getField` from mock data as the field-definition source; in a real DB-backed system this is the same seam).
- **Dew hours**: estimated from temp vs dew-point (hours where `temp ≤ dewpoint` approximation from daily means) — flagged as an estimate in code comments. No exact free source exists.
- Field centroid comes from `getField(fieldId).centroid`.

**1e. `lib/gdd.ts`** — `computeGddCumulative(daily: {maxC, minC}[], baseTempC): number`. Pure util; mock could later reuse it for consistency (optional).

**1f. `MapView.tsx` async values**
- Add `useEffect` that `fetch("/api/map/layers?date=" + selectedDate)` → setState values map → merge into `fieldFeatures(layer, fields, values)` → `source.setData(...)`. Depends on `[selectedDate]` (refetch on date change; layer change is a client-side recompute, no refetch).
- Loading state: show polygons in the no-data tint (`layerColor` already returns `#9CA3AF` for null) until values arrive — matches the existing skeleton-first convention.

**1g. Registry env-gating (`lib/providers/registry.ts`)**
- `weatherProvider = process.env.OPEN_METEO_BASE_URL !== "mock" ? new OpenMeteoWeatherProvider() : new MockWeatherProvider()` — default to real when the flag is unset, but keep an explicit `mock` escape hatch so dev/tests stay deterministic. (Open-Meteo needs no key, so real-by-default is safe.)

### Phase 2 — Sentinel-2 NDVI raster

**2a. New `lib/providers/sentinel-auth.ts` (server-only)** — `getSentinelToken(): Promise<string>`
- POST `https://services.sentinel-hub.com/auth/realms/main/protocol/openid-connect/token` with `grant_type=client_credentials`, `client_id`, `client_secret`, `Content-Type: application/x-www-form-urlencoded`.
- Module-level cache of `{ token, expiresAt }`. Sentinel Hub rate-limits token requests (HTTP 429), so reuse until expiry (decoded from JWT `exp`, or default ~10 min with a safety margin). Re-fetch on 401.

**2b. New `lib/providers/sentinel.ts`** — `Sentinel2SatelliteProvider implements ISatelliteProvider`
- `getNdviTile(z, x, y, date, bbox)` → fetch a Sentinel-2 NDVI tile via the WMS endpoint (`https://services.sentinel-hub.com/ogc/wms/{INSTANCE_ID}` or the Process API) with an embedded `evalscript` computing NDVI from B04/B08 and your existing color ramp, `MAXCC` cloud cover, `TIME=date`. Returns the image `ArrayBuffer`.
- `getNdviAt(fieldId, date)` / `getNdviSeries(fieldId)` → Process API *statistics* endpoint for the field polygon (zonal mean NDVI) — lighter than tiles, powers the legend/DevicePanel number.
- Env-gated: requires `SENTINEL_CLIENT_ID` + `SENTINEL_SECRET` (+ optional `SENTINEL_INSTANCE_ID`); falls back to mock if absent.

**2c. New BFF tile proxy `app/api/tiles/ndvi/[z]/[x]/[y]/route.ts`**
- `GET /api/tiles/ndvi/{z}/{x}/{y}?date=...` → calls `satelliteProvider.getNdviTile(...)`, returns the image with `Content-Type: image/png` and a long `Cache-Control` (tiles are immutable for a given date+xyz). This is the secure token-injection point.
- 404/placeholder when Sentinel unavailable.

**2d. `MapView.tsx` raster layer**
- When `layer === "ndvi"`: add a Mapbox `raster` source `{ tiles: ["/api/tiles/ndvi/{z}/{x}/{y}?date=" + selectedDate], tileSize: 256 }` + a `raster` layer with opacity ~0.55, drawn above the satellite basemap. Hide/empty the polygon fills (imagery carries the data) but keep outlines + selection highlight.
- When switching to a non-NDVI layer: remove the raster source/layer, restore polygon fills.
- The raster source URL must rebuild when `selectedDate` changes (new query param) — handle in the existing date effect.

**2e. Register Sentinel provider** in `registry.ts` (env-gated as above).
